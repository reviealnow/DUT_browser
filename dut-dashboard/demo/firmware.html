Images already in the shared Files workspace can be picked directly — the same endpoint, so they stay listed, checksummed and attributable.
Flow demonstration only. This standalone page does not upload a file, run the backend's validation, contact a DUT, or persist the management address. What it does reproduce is which pairings the service refuses, in the order it checks them.
The two paths are not interchangeable. The management API takes the encrypted image; the web-UI upload takes the signed .sig. Feeding one the other's image is what produced Can't open FW.signauture.st1 on a real unit — the transport was fine, the image was wrong. This screen keeps that rule because a demo of a flasher that blurred it would be teaching the one mistake worth avoiding.
